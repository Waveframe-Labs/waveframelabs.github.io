Reference Scenarios · 2026-09

Concrete governance outcomes at a mediated boundary.

These are reference patterns, not customer claims. Each example assumes the consequential application capability is routed through Guard and that the selected authority is current and verifiable.

Operational patterns

A blocked result applies to the mediated capability being evaluated. Deployment architecture must still control any alternate route to the same underlying system.

Finance Governance

Amount exceeds an approved threshold

An automated finance workflow proposes an allocation above the threshold defined by its selected authority, but the required approval evidence is absent.

Evaluation: actor, amount, account target, and authority identity are bound to the proposal before deterministic evaluation.

Result: BLOCK — the mediated finance operation does not proceed.

Repository Governance

Create is requested under modify-only authority

A repository workflow requests a new file while the selected catalog-3 authority grants only modification for the same path scope.

Evaluation: Guard 0.19.0 and Compiler 0.5.0 keep create and modify as independent action categories. A modify grant does not imply create.

Result: BLOCK — the repository create operation does not proceed.

Access Governance

Requested role is outside the actor's scope

An identity-management workflow proposes a role change that is not permitted for the current actor under the selected authority.

Evaluation: actor identity, requested target, and authority are evaluated together.

Result: BLOCK — the mediated role change does not proceed.

Publication Integrity

Authority identities do not agree

A runtime request references a publication whose contract and receipt identities do not match the selected authority reference.

Evaluation: the publication is rejected before it can establish runtime authority.

Result: BLOCK — no usable authority is established.

Human-Confirmed Policy

Only part of a policy statement is supported

Ledger identifies supported controls and leaves the remaining source meaning explicit for human review rather than silently converting it.

Publication: only confirmed, supported meaning enters the published authority record.

Result: the published authority remains narrower than the original prose when support is incomplete.

Allowed Action

Current authority matches the requested operation

An application request matches the actor, action category, target scope, and required runtime facts in the selected authority.

Evaluation: the deterministic result is allowed and the mediated application callback may continue.

Result: ALLOW — the observed outcome is recorded as runtime evidence.

What the scenarios demonstrate

Waveframe separates proposed work from approved authority. Ledger publishes the reviewed meaning, the compiler turns that meaning into deterministic contracts, Guard mediates the real application call, CRI-CORE evaluates admissibility, and evidence records the resulting boundary outcome.
