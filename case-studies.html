Reference Scenarios · 2026-09

Concrete mediated actions. Deterministic outcomes.

These are reference patterns, not customer claims. Each example assumes the sensitive capability is actually routed through the Guard boundary and that alternate mutation paths are independently restricted where required.

Operational patterns

The guarantee is path-specific: a BLOCK prevents the wrapped callback from running. It does not prove that an actor lacks every other route to the same underlying capability.

Finance Governance

Budget allocation exceeds approved authority

Proposed tool call: an allocator agent attempts a 12,500-unit allocation where the selected authority requires approval evidence above the configured threshold.

Mediated evaluation: Guard binds actor, amount, target account, and exact authority; CRI-CORE returns blocked because required approval evidence is absent.

Result: BLOCK — allocation callback never runs.

Repository / Deployment Governance

Agent tries to modify a protected deployment path

Proposed tool call: change a production deployment file while authority permits an exact documentation target but denies the deployment/ prefix.

Mediated evaluation: Guard 0.18.0 uses repository_tool, canonical repository-relative target identity, and the compiler-defined literal scope. Deny wins.

Result: BLOCK — repository mutation callback never receives a usable target.

Privileged Access Governance

Service account requests administrator role

Proposed tool call: grant an organization-admin role through a Guard-wrapped identity mutation function.

Mediated evaluation: actor role and target identity are bound to the proposal; the selected authority does not permit that actor to perform the privileged mutation.

Result: BLOCK — permission-change callback does not execute.

Authority Publication Integrity

Runtime receives an incomplete or mismatched Ledger publication

Proposed tool call: evaluate against a publication package whose bundle/receipt/contract identities do not match.

Mediated evaluation: Guard verifies the complete supported publication before evaluation or cache use. A mismatched publication is not treated as authority.

Result: BLOCK / resolution failure — no governed mutation permission is established.

Human-Confirmed Translation

Model proposes two controls from one source clause

Authoring event: an external model proposes bounded controls while part of the clause remains unsupported.

Publication evaluation: Ledger requires each proposed control to be independently confirmed and the residual unsupported span to remain explicit and acknowledged.

Result: only confirmed controls can enter published authority; residual meaning remains non-executable.

Allowed Mediated Action

Approved allocation reaches the callback exactly once

Proposed tool call: an authorized allocator requests a 500-unit allocation under a matching published authority.

Mediated evaluation: authority resolves, proposal and runtime facts validate, CRI-CORE allows, then Guard invokes the exact wrapped callback and records the outcome.

Result: ALLOW — the mediated callback executes once.

What the scenarios demonstrate

Waveframe does not ask the model to self-police. The application exposes a mediated capability; published authority defines what that capability may do; Guard evaluates the actual call immediately before mutation; CRI-CORE returns the admissibility decision; and evidence records what happened at that boundary.
