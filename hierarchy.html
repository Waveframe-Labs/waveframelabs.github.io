Execution Pipeline

What happens when an AI tries to take an action?

When an AI proposes something — move money, deploy code, approve a decision — that action should not execute immediately.

It must pass through a control layer that decides:

✓ allow the action
✗ block it before execution

The Execution Pipeline

1. Define constraints

Rules are defined as enforceable contracts: required roles, approvals, and constraints.

These rules determine what must be true before an action is allowed.

2. Normalize the action

The proposed action is converted into a structured format: who initiated it, what it changes, and what evidence supports it.

3. Evaluate

The action is passed into CRI-CORE.

It checks: roles, approvals, integrity, and required artifacts.

4. Decide

The system returns a single result:

✓ allowed
✗ blocked

If blocked, the action never executes.

Where this sits

This pipeline sits directly at the execution boundary — the moment a decision becomes a real-world action.

Everything upstream can recommend, generate, or suggest.

This layer decides whether anything actually happens.

Components

Contract Compiler → defines enforceable rules

Proposal Normalizer → structures actions

CRI-CORE → evaluates and decides
