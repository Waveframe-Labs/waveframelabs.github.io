Execution Pipeline

What happens when an AI tries to take an action?

When an AI system proposes something — move money, deploy code, approve a decision — that action does not execute immediately.

It passes through a control layer that determines: should this action be allowed to execute?

The Execution Pipeline

1. Define constraints

Organizational rules are defined as enforceable contracts: required roles, approvals, and constraints.

These are compiled into a structured format that can be evaluated deterministically.

2. Normalize the action

The proposed action is converted into a canonical structure: who initiated it, what it changes, and what artifacts support it.

3. Evaluate

The action is passed into CRI-CORE.

The system checks: roles, approvals, integrity, and required evidence.

4. Decide

The system returns a single result:

✓ allowed to execute ✗ blocked before execution

Where this fits

This pipeline sits directly at the execution boundary — the moment where a decision becomes a real action.

Everything upstream defines what should happen. This layer decides whether it actually can happen.

Components

Contract Compiler — defines enforceable rules

Proposal Normalizer — structures incoming actions

CRI-CORE — evaluates and decides
