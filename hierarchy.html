Canonical Architecture · 2026-09

Authority is published before execution is mediated.

Waveframe separates what a policy means, what authority was actually approved, whether a proposed action is admissible, whether the mediated callback executed, and what evidence was durably preserved.

Architecture diagram

The runtime begins at Guard's mediated tool boundary. Guard resolves authority and prepares evaluation; CRI-CORE decides admissibility; only then may Guard invoke the wrapped mutation.

Boundary principles

Policy prose is not runtime authority.Ledger must turn supported meaning into explicit, reviewed authority. Unsupported or residual meaning stays visible rather than becoming implicit behavior.
Model output is a proposal, not authority.Ledger 0.8.0 permits bounded translation proposals, but each control must be independently confirmed by a human before publication.
Guard owns mediation, CRI-CORE owns the decision.The call reaches Guard first. Guard resolves and verifies the selected authority, normalizes the real call into evaluation inputs, and invokes CRI-CORE immediately before the callback.
The guarantee is path-specific.Only calls routed through the wrapped boundary are governed by Guard. Alternate functions, APIs, shells, processes, credentials, or writers require independent restriction.

Four operational flows

Authority Flow

  1. Organization supplies source policy and the intended governance domain.
  2. Ledger classifies supported meaning and surfaces ambiguity, unsupported spans, and required answers.
  3. External/model translation may propose controls, but human reviewers confirm each control and acknowledge residual meaning.
  4. Contract Compiler deterministically produces the compiled runtime authority and hash.
  5. Ledger publishes the approved authority bundle, commitment, receipt, lineage, and registry identity.
  6. Cloud may distribute the tenant-scoped publication; local resolution remains possible.

Proposal Flow

  1. The agent or application calls the Guard-wrapped tool with real arguments.
  2. Guard derives the mediated action, target, actor identity, selected authority, and only approved decision-relevant facts.
  3. Proposal Normalizer validates and assembles the canonical proposal without inventing contract truth.
  4. The proposal and exact compiled authority are passed to CRI-CORE.

Execution Flow

  1. Guard.local() or Guard.cloud() receives the tool call.
  2. Guard verifies the authority publication before using or caching it.
  3. CRI-CORE returns the deterministic admissibility decision.
  4. If blocked, the wrapped callback does not run.
  5. If allowed, Guard invokes the exact mediated callback. Repository writes require repository_tool and its bound target capability.
  6. Guard records the callback/mutation outcome without guessing unknown physical state.

Evidence Flow

  1. Guard binds decision evidence to actor, authority, proposal, target, and mediation context.
  2. Execution/mutation attestations record whether the callback ran, failed, or did not run.
  3. Cloud can preserve governed evidence and return package, receipt, and proof identifiers.
  4. Cloud preservation does not replace the local final mutation attestation, and replay reproduces logical decisions rather than physical mutation.

Identity carried across the boundary

The replayable thread is explicit identity, not prose inference. The selected publication binds the runtime contract and its provenance; the proposal carries that exact authority into evaluation; the evidence binds the resulting decision back to the mediated call.

Current release boundary

Published runtime

Guard 0.18.0, Ledger 0.8.0, Compiler 0.4.0, and the compatible Proposal Normalizer 0.2.0 are the current public lines. CRI 0.13.0 remains the PyPI baseline accepted by Guard 0.18.0.

Released but not PyPI baseline

CRI-CORE v0.14.0 is released on GitHub with strict-by-default evaluation. Its release record still marks PyPI publication pending.

Merged Cloud source

Tenant v2/v3 publication serving and hosted translation/Console workflow code has merged after Cloud v0.5.7. The website does not treat those source merges as a newer hosted release.

Commercial boundary

Cloud, Console, Ledger Workspace, Guard Inspector, and multi-tenant operations remain separate from the Apache-2.0 Guard Core SDK.
