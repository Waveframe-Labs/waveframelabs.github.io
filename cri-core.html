Execution Control

CRI-CORE

CRI-CORE sits directly before execution and decides:

✓ allow this action to run ✗ block it before it happens

It does not monitor or explain decisions. It controls whether they are allowed to execute.

Why This Exists

AI systems can now take real actions — moving money, deploying code, changing infrastructure.

Most systems detect problems or audit after the fact.

But by the time something is logged, the action has already happened.

CRI-CORE enforces a decision at the only point that matters: before execution.

What It Does

  • Evaluates every proposed action before it executes.
  • Enforces required roles and approvals (e.g. proposer, approver).
  • Validates that inputs and artifacts have not been tampered with.
  • Ensures the action matches a defined contract.
  • Returns a single decision: commit_allowed = true | false.

Current State

Public Distribution

CRI-CORE is available as an installable Python package.

pip install cricore

Design Constraints

  • Deterministic — same input, same result.
  • Domain-agnostic — works across finance, infrastructure, operations.
  • Non-judgmental — does not decide if something is “good.”
  • Binary output — the action either executes or it does not.
