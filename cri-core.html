Layer 3 — Enforcement

CRI-CORE

CRI-CORE is a deterministic structural enforcement kernel for governed state transitions. It evaluates structural, authority, integrity, binding, sealing, and publication constraints, then returns a single authoritative commit decision.

Why CRI-CORE Exists

AI-assisted systems increasingly generate recommendations that influence real operational decisions. The highest-risk moment is the execution boundary — the point where a recommendation becomes a state mutation. CRI-CORE exists to ensure that state changes only occur when declared responsibility and integrity constraints pass deterministic validation.

CRI-CORE does not interpret domain policy or mutate state. It authorizes (or rejects) a proposed mutation attempt based on declared contracts and verifiable run evidence.

Core Capabilities

  • Deterministic pipeline enforcement for governed transition attempts.
  • Structural contract evaluation and version gating.
  • Authority and responsibility checks (role satisfaction and structural admissibility).
  • Cryptographic integrity verification for declared artifacts and run inputs.
  • Publication-stage commit gating via a single authoritative commit_allowed signal.
  • Machine-readable enforcement outputs for downstream logging, audit, and replay.

Current State

Public Distribution

CRI-CORE is distributed as an installable Python package:

pip install cricore

Scope

  • Deterministic and domain-agnostic.
  • Invocation-bound: CRI-CORE evaluates a proposed transition attempt and returns a decision.
  • Non-semantic: it does not decide whether a claim is “true” or “good,” only whether a mutation is authorized under declared constraints.
