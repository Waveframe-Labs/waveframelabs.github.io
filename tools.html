Tooling

Tools

Deterministic tooling that validates artifacts, preserves provenance, and produces citable outputs for governed workflows. Tools do not define authority or workflow method; they implement and reflect decisions made upstream.

Purpose

Tools exist to make governed workflows reproducible, auditable, and mechanically checkable. They operate under governance (L0) and method (L1) constraints and may not redefine either.

Core Tooling

Stamp

Deterministic artifact and metadata validation tooling. Stamp extracts metadata, validates it against declared schemas, normalizes failures into structured diagnostics, and separates machine-safe fixes from human judgment.

Stamp explains what is wrong and what action is required; it does not enforce state mutation or judge content meaning.

PyPI: waveframe-stamp  ·  Install: pip install waveframe-stamp  ·  GitHub: Waveframe-Stamp

Waveframe PDF Forge

Deterministic Markdown → PDF publication pipeline used to generate Scholar-ready artifacts. Forge freezes validated sources for citation and distribution while preserving provenance.

Waveframe Publications Repository

Canonical Markdown source files used by Forge to generate publication artifacts.

Related Upstream Components

Glyphtrace (Layer 2 — Language & Ontology)

Symbolic compression format for representing claims and reasoning compactly. Glyphtrace is not a tool; it is a representation layer consumed by validation, enforcement, and publication systems.

Relationship to the Aurora Stack

  • L0–L1: Tools operate under governance and method constraints.
  • L4: Tools integrate with enforcement surfaces where state mutation must be gated (CRI-CORE).
  • L5: Tools produce frozen outputs and publishable artifacts (Forge, publications sources).
  • L6: Tools support demonstrations that exercise the validation and enforcement pipeline.
